# Exercise 4: видео и что нужно выучить

Этот файл — учебный маршрут по Demo 4.1–4.10. Не нужно смотреть все видео сразу. Перед каждым Demo смотри только соответствующий раздел, а затем переходи к коду.

Большинство видео на русском. Для англоязычных видео можно включить русские автоматические субтитры на YouTube.

## 4.1 — JSX, компоненты, props и children

Основное видео: [Learn TypeScript with React — Austin Davis](https://www.youtube.com/watch?v=DxqiBrERv6o)

Смотреть:

- `11:02–18:47` — типизация props и `children`;
- `21:41` — передача объекта через props, если потребуется дополнительный пример.

Дополнительное объяснение на русском: [Props в React: что такое props и зачем нужен children](https://www.youtube.com/watch?v=jtC_gyCIVdU)

Что нужно понять:

- React-компонент — это функция, которая возвращает JSX;
- props — входные параметры компонента;
- TypeScript проверяет обязательные и необязательные props;
- неверный тип или отсутствие обязательного prop показывает ошибку до запуска приложения;
- `children` — содержимое между открывающим и закрывающим тегами компонента;
- `children` удобно использовать для компонентов-обёрток, например `Panel`, `Card` или `Section`;
- именованный prop используют для значения с конкретным назначением;
- React должен самостоятельно управлять созданными им DOM-элементами.

На практике в задании:

- сделать небольшие компоненты для людей, локаций и событий;
- описать их props с помощью TypeScript;
- сделать хотя бы один компонент-композицию с `children`.

## 4.2 — Условный рендеринг

Видео: [JSX в React: условный рендеринг и списки — Friendly Frontend](https://www.youtube.com/watch?v=8EXUlJ80Vec)

Смотреть: `11:46–15:25`.

Что нужно понять:

- тернарный оператор: `condition ? A : B`;
- короткое условие: `condition && A`;
- ранний возврат из компонента: `if (...) return ...`;
- `return null` означает, что компонент ничего не добавляет в DOM;
- пустой `<div>` всё равно создаёт настоящий DOM-элемент;
- выражение `0 && <Component />` может вывести на страницу число `0`;
- условия можно использовать для текста, badge, CSS-класса и empty state.

На практике в задании:

- показать минимум два реальных условия интерфейса;
- использовать минимум два разных способа условного рендеринга;
- уметь объяснить, почему выбран именно этот способ.

## 4.3 — Рендеринг коллекций

Видео: [JSX в React: условный рендеринг и списки — Friendly Frontend](https://www.youtube.com/watch?v=8EXUlJ80Vec)

Смотреть: `15:25–18:01`.

Что нужно понять:

- `.map()` преобразует массив данных в массив JSX-элементов;
- каждый человек, локация или событие может отображаться отдельным компонентом;
- `key` устанавливают на самый верхний JSX-элемент, возвращаемый из `.map()`;
- для `key` следует использовать постоянный ID: `person.id`, `location.id` или `event.id`;
- `key` нужен самому React и автоматически не передаётся компоненту как обычный prop.

На практике в задании:

- отобразить через `.map()` людей;
- отобразить через `.map()` локации;
- отобразить через `.map()` события Timeline;
- использовать стабильный ID в каждом списке.

## 4.4 — Стабильные key и идентичность элементов

Видео: [Why You Should Never Use Index as Key in React Lists](https://www.youtube.com/watch?v=SRjN8SHOS6U)

Видео на английском, но оно показывает именно видимую ошибку, которая появляется при использовании индекса.

Что нужно понять:

- `key` обозначает постоянную идентичность записи;
- индекс обозначает только текущее положение записи в массиве;
- после удаления, фильтрации или перестановки `key={index}` может связать старое состояние с другой записью;
- текст в input или локальное состояние компонента может «переехать» к неправильному элементу;
- правильный вариант для наших данных — `key={item.id}`;
- индекс подходит только для полностью статичного списка, который никогда не меняет порядок.

На практике в задании:

- сначала специально воспроизвести проблему с `key={index}`;
- затем заменить индекс стабильным ID;
- проверить фильтрацию или перестановку ещё раз;
- уметь своими словами объяснить причину ошибки.

## 4.5 — Feature/container и presentational-компоненты

Видео: [Умные и глупые компоненты в ReactJS](https://www.youtube.com/watch?v=zeS3MrlF5dw)

Термины в видео немного старые, но принцип соответствует заданию.

Что нужно понять:

- feature/container-компонент выбирает и подготавливает данные;
- presentational-компонент получает готовые props и отображает интерфейс;
- один большой компонент не должен одновременно искать данные, преобразовывать их и рисовать всю страницу;
- после разделения у каждого компонента должна остаться одна понятная ответственность;
- presentational-компоненту не запрещён любой локальный UI-state: важно, чтобы он не управлял бизнес-логикой всей feature.

Пример разделения:

- `PeoplePage` — feature/container-компонент;
- `PersonList` — компонент списка;
- `PersonCard` — presentational-компонент одной записи.

## 4.6 — Структура проекта по features

Видео: [Архитектура React-приложения и Feature-Sliced Design — Friendly Frontend](https://www.youtube.com/watch?v=KnwduChQuuo)

Смотреть:

- `00:35` — зачем проекту структура;
- `03:18` — проблемы неудачной структуры;
- `09:57` — понятие feature;
- `16:43` — понятие shared.

Что нужно понять:

- структура по типам файлов и структура по функциям приложения решают разные задачи;
- код Dashboard лучше хранить рядом с Dashboard;
- код People/Locations лучше хранить рядом с этой feature;
- код Timeline лучше хранить рядом с Timeline;
- в `shared` следует переносить только то, что действительно используют разные features;
- co-location означает, что связанные компонент, типы и вспомогательная логика находятся рядом.

Важно: полностью внедрять сложную методологию FSD в этом упражнении не требуется. Нам нужны идея группировки по features и понятная граница между feature-кодом и `shared`.

## 4.7 — Переиспользуемые UI-компоненты

Видео: [Props в React: что такое props и зачем нужен children — Friendly Frontend](https://www.youtube.com/watch?v=jtC_gyCIVdU)

Особенно полезная часть начинается примерно с `06:50`.

Что нужно понять:

- один `Badge`, `Panel` или `Card` можно использовать с разными данными;
- изменяемые значения передаются через props;
- общая разметка и поведение остаются внутри компонента;
- хороший reusable-компонент должен использоваться минимум в двух разных местах;
- его API не должен состоять из специальных флагов только для одной feature;
- не нужно заранее обобщать компонент, если переиспользования пока нет.

На практике в задании:

- выбрать небольшой повторяющийся UI-элемент;
- описать его props через TypeScript;
- использовать его минимум в двух разных местах приложения.

## 4.9 — Параметр маршрута `:personId`

Видео: [useParams: динамические маршруты — Web-garage](https://www.youtube.com/watch?v=AxrtrU5Wxy0)

Видео короткое, поэтому его лучше посмотреть целиком.

Что нужно понять:

- `:personId` обозначает изменяемую часть маршрута `/team/people/:personId`;
- `useParams()` позволяет получить значение `personId` из URL;
- в TypeScript параметр может иметь тип `string | undefined`;
- по полученному ID можно найти человека через `people.find(...)`;
- ссылка на карточке человека должна вести на настоящий маршрут;
- неизвестный ID должен показать not-found, а не уронить приложение;
- `/people/nova-byte` и `/people?person=nova-byte` имеют разный смысл.

Актуальное описание API: [официальная документация useParams](https://reactrouter.com/api/hooks/useParams).

## 4.10 — Query-параметры

Видео: [Параметры поиска в React Router](https://www.youtube.com/watch?v=C-AFpwNrPRU)

Видео короткое, поэтому его лучше посмотреть целиком.

Что нужно понять:

- query string находится после символа `?`, например `?person=nova-byte`;
- `useSearchParams()` позволяет прочитать query-параметры;
- `searchParams.get("person")` возвращает значение параметра или `null`;
- значение из URL нужно проверить перед использованием;
- на основании query-параметра можно вычислить отфильтрованный Timeline;
- URL с фильтром можно сохранить, скопировать и открыть после reload;
- route-параметр обычно выбирает конкретный ресурс;
- query-параметр обычно изменяет фильтр или представление страницы.

В рамках Demo 4.10 пока не требуется делать dropdown интерактивным. Достаточно прочитать параметр из URL и определить первоначальный список событий.

Актуальное описание API: [официальная документация useSearchParams](https://reactrouter.com/api/hooks/useSearchParams).
