# Demo 5.6 – Passing Callbacks Downward

## 1. EvidenceDetail
- `draftNote` ist lokaler State.
- Beim Tippen wird nur `draftNote` geändert.
- Beim Speichern:
  `onSaveNote(evidence.id, draftNote)`

## 2. App
- `App` besitzt den gemeinsamen `notes`-State.
- `handleSaveNote` ist der Parent-Callback.
- Ablauf:
  1. neues `nextNotes`-Objekt erzeugen
  2. `setNotes(nextNotes)`
  3. Notes im `localStorage` speichern

## 3. Callback-Fluss
`App`
↓
`AppRoutes`
↓
`EvidencePage`
↓
`EvidenceDetail`

- State und Callback werden über Props nach unten weitergegeben.
- Das Child verändert den Parent-State nicht direkt.

## 4. Console Logs
Beim Klick auf **Save note**:

`EvidenceDetail → save requested`  
→ Child ruft den Callback auf.

`App → handleSaveNote received`  
→ App erhält die Anfrage.

`App → notes state update scheduled`  
→ App aktualisiert den gemeinsamen State.

Später im Workspace:

`NotesList → rendered with updated notes`  
→ Die aktualisierten Notes wurden neu gerendert.

## 5. Nach dem Speichern
- `EvidenceDetail` ruft den Callback auf.
- `App` aktualisiert den State.
- React rendert mit dem neuen State erneut.

## 6. Workspace
`App`
↓
`AppRoutes`
↓
`WorkspacePage`
↓
`NotesList`

- `WorkspacePage` gibt `notes` nur weiter.
- `NotesList` filtert vorhandene Notes und zeigt sie an.

## Kernaussage
**Parent besitzt den State → Callback geht nach unten → Child ruft ihn auf → Parent aktualisiert den State.**
